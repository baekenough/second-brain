계획서·산출 문서를 쓸 때: **1,000줄 상한을 지키고**, 코드는 최소 스니펫만 넣고 나머지는 산문으로 지시한다. 참조 문서는 `Grep`으로 위치를 먼저 찾고 `Read`에 `offset`/`limit`을 걸어 필요한 절만 읽는다(한 번에 400줄 이하). **섹션 제목만 있는 골격 파일을 먼저 Write하고** 그 다음 섹션을 하나씩 채운다.

**Why:** 과거 세션에서 서브에이전트가 대용량 참조 문서(plans/는 70~100KB)를 통째로 읽다가 233k 토큰을 쓰고 산출물을 하나도 못 만든 사고가 있었다. 또 기존 계획서가 100KB까지 부풀어 후속 에이전트의 컨텍스트를 태운 전례가 있다.

**How to apply:** 계획서/설계 문서 작성 지시를 받으면 착수 즉시 (1) 목차 grep, (2) 골격 Write, (3) 섹션별 채우기 순서로 간다. 다 쓴 뒤 `wc -l`로 상한을 확인하고, 넘으면 코드 블록 압축·중복 산문 제거·구분선 정리로 줄인다. 상한 준수가 writing-plans 스킬의 "bite-sized 스텝" 관습보다 우선한다(스텝을 병합해도 검증 명령과 기대 결과는 유지한다).
