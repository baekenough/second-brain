`internal/telemetry` (new package, `InitOTel(ctx, endpoint, publicKey, secretKey) (shutdown func, err error)`) wires OpenTelemetry spans to a self-hosted Langfuse instance via OTLP/HTTP. Implemented 2026-08-17 per `sb-agent-platform/docs/2026-08-17-llm-observability-implementation.md` Task 2/3. Deployment of the Langfuse stack itself (Task 1) is out of scope of second-brain — that lives in the sibling ops repo.

**Why:** Langfuse has no Go SDK; OTLP/HTTP direct to Langfuse's `/api/public/otel` receiver is the only integration path. The plan mandated non-blocking export (`BatchSpanProcessor`, never `WithBlocking()`) and no PII (prompt/response bodies) in span attributes.

**How to apply / non-obvious decisions to preserve on future edits:**
- GenAI attribute keys (`gen_ai.system`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`) are defined as **plain string constants** in `internal/telemetry/attrs.go` (`AttrGenAI*`), NOT sourced from `go.opentelemetry.io/otel/semconv/*`. The vendored semconv (v1.40.0) renamed `gen_ai.system`→`gen_ai.provider.name`; pinning a semconv version would silently drift from what Langfuse's OTLP receiver expects. Do not "fix" this by importing semconv later without checking Langfuse's currently-expected key names first.
- Every package (`internal/llm`, `internal/search`, `internal/collector/whisper.go`) calls `otel.Tracer(name)` **fresh inside each function** (a small `tracer()`/`embedTracer()`/`whisperTracer()` helper), never as a package-level `var tracer = otel.Tracer(...)`. Reason: OTel Go's global-provider delegation only swaps a pre-existing tracer handle's delegate on the *first* `SetTracerProvider` call (`sync.Once` internally) — a package-level var created before tests call `SetTracerProvider` a second/third time would keep pointing at the FIRST test's provider forever. Lazy per-call lookup avoids this entirely and is required for test isolation across multiple `*_otel_test.go` files reusing the same in-memory-exporter pattern.
- Retry-wrapping span structure (`internal/llm.CompleteWithMessages`): ONE parent span `llm.complete` wraps the whole retry loop, ONE child span `llm.complete.attempt` per HTTP attempt (`llm.retry.attempt` int attribute = zero-based attempt index). `StreamWithMessages` gets a single `llm.stream` span (no retry, per existing "never retry once streaming started" design).
- `internal/search.EmbedClient`: `Embed`→`embedding.single` span; `EmbedBatch`→`embedding.batch` parent span, `embedBatchOnce`→`embedding.batch.subbatch` child span per sub-batch dispatched (tagged `embedding.batch_size`).
- `internal/collector/whisper.go` `transcribeFile`→`transcription` span. `gen_ai.system` value is `"whisper-self-hosted"` vs `"openai"` based on `isLocalWhisperEndpoint` — computed ONCE per `CollectStream` cycle and threaded through `streamPending`→`buildDocument`→`transcribeFile` as an `isLocal bool` param (avoids a DNS lookup per file in the worker pool).
- PII policy for spans: attributes carry only model/token/latency/error metadata — **never prompt or completion text**. This mirrors the collector's existing "PII masking is off elsewhere, defended by access control" stance for storage, but tracing deliberately stays metadata-only regardless (see code comments in the plan doc and in `client.go`/`embed.go`/`whisper.go`).
- Test pattern for span assertions: `tracetest.NewInMemoryExporter()` + `sdktrace.NewTracerProvider(sdktrace.WithSyncer(exp))` + `otel.SetTracerProvider(tp)`, restored to `noop.NewTracerProvider()` via `t.Cleanup`. These tests deliberately do NOT call `t.Parallel()` (unlike every sibling test in the same files, which does) — Go's test runner completes all non-`t.Parallel()` tests to full completion before resuming any paused parallel ones, so this avoids races on the global TracerProvider without needing per-test locking.
- `go.mod`: added `go.opentelemetry.io/otel/sdk` and `.../exporters/otlp/otlptrace/otlptracehttp` as direct deps (as instructed); `go mod tidy` additionally promoted `go.opentelemetry.io/otel` and `go.opentelemetry.io/otel/trace` to direct too, since the instrumentation code imports them directly (unavoidable — you can't call `otel.Tracer`/use `trace.Tracer` types without importing them).
- New env vars (all optional, default `""` = fully disabled/no-op): `LANGFUSE_OTLP_ENDPOINT` (the OTLP **base** URL, e.g. `.../api/public/otel`), `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`. Wired in `internal/config/config.go` `Load()` and consumed in `cmd/server`, `cmd/collector`, `cmd/eval` `run()` via `telemetry.InitOTel` + a deferred, 5s-timeout-wrapped shutdown.
- **Real deployment (2026-08-17)**: OTLP base endpoint is `http://100.77.20.12:3300/api/public/otel` (Tailscale-interface binding of `langfuse-web`, port 3300 — NOT the public `https://langfuse.<domain>` hostname, which sits behind Cloudflare Access and silently swallows server-to-server OTLP POSTs via a 302-to-login). Keys are on disk at `~/.lf-pub` / `~/.lf-sec` on the dev machine (42 bytes each) — never print/hardcode them; read via env vars only.
- **CRITICAL bug found + fixed via live verification, not docs**: `InitOTel` originally used `otlptracehttp.WithEndpointURL(endpoint)` with the endpoint used **verbatim** as the full traces URL. This is WRONG for Langfuse — POSTing to the bare `.../api/public/otel` path hits Langfuse's own Next.js web app router and returns its normal 404 page (a *valid* route, just not the OTLP one), which otlptracehttp treats as an ordinary failed export and silently drops the span — no crash, no visible error unless someone inspects stderr closely. Verified empirically with `curl`: `POST /api/public/otel` → 404 (Next.js HTML); `POST /api/public/otel/v1/traces` → 401 (real OTLP route, needs auth) — confirming the receiver actually lives at `{base}/v1/traces`, matching the standard `OTEL_EXPORTER_OTLP_ENDPOINT` convention (base URL + auto-appended `/v1/traces`) that Langfuse's own docs presumably rely on but which `WithEndpointURL` (used-as-is, no auto-append) does not replicate on its own. **Fix**: `InitOTel` now does `tracesURL := strings.TrimRight(endpoint, "/") + "/v1/traces"` before calling `WithEndpointURL`. Confirmed end-to-end with a throwaway `go run` smoke test against the real deployment (created in `cmd/`, deleted immediately after, never committed) — silent 404-drop before the fix, clean successful export after. `internal/telemetry/otel_test.go`'s `TestInitOTel_ConfiguresRealProviderWhenEndpointSet` now asserts the exact exported path (`/api/public/otel/v1/traces`) via a stub server that 404s anything else, specifically to catch a regression of this bug.
- **Lesson**: when a plan/doc gives you an endpoint value for a third-party OTLP receiver, verify the actual ingestion path against the live service (`curl -X POST` to check for 401 vs 404) rather than trusting `{endpoint}` is directly POST-able — third-party HTTP APIs commonly document a "base URL" that still needs a standard suffix appended, and `otlptracehttp.WithEndpointURL` does NOT auto-append `/v1/traces` the way `WithEndpoint`/the `OTEL_EXPORTER_OTLP_ENDPOINT` env var convention does.
