# R007: Agent Identification Rules

**Priority**: MUST | Every response must begin with an agent identification header. Enforced via PostCompact hook and CLAUDE.md injection.

## Overview

R007 ensures users always know which agent is active. The identification header must appear at the start of every response — even after context compaction. The PostCompact hook re-injects this rule to prevent compaction amnesia.

## Full Format

```
┌─ Agent: {agent-name} ({agent-type})
├─ Skill: {skill-name} (if applicable)
└─ Task: {brief-task-description}
```

Default (no specific agent): `┌─ Agent: claude (default)`

## Simplified Format

For brief responses: `[mgr-creator] Creating agent structure...`

With skill: `[fe-vercel-agent → react-best-practices] Analyzing...`

## Routing Context

| Context | Identification |
|---------|---------------|
| No routing active | `claude (default)` |
| secretary-routing | `claude (secretary-routing)` |
| Skill invocation | `claude → {skill-name}` |

## Skill Invocation Format (Correct)

```
┌─ Agent: claude → {skill-name}
└─ Task: {brief-task-description}
```

Skill name MUST be integrated into the identification block, not displayed separately.

## Enforcement

- Advisory PostToolUse hook warns on missing identification
- PostCompact hook re-injects after context compaction
- Hard enforcement candidate if violation rate exceeds 20% (see [[r021]])

## Context Drift Mitigation (Multi-Turn Sessions)

In long sessions, prompt-based R007 can drop out of active context. Four high-risk windows have produced real omissions:

| Window | Why |
|--------|-----|
| Turn opens with a subagent completion notification | Not user input — weak trigger to recall the rule |
| 5+ chained tool calls in a diagnostic sequence | Rule only present early in context, never re-checked |
| Aggregating results from 3+ parallel agents | Focus on synthesis, header skipped |
| Turn resumes immediately after context compaction | Summary feels like it replaces the rule body; the resume instruction to skip meta-preamble gets over-applied to the header |

**Self-check**: explicitly verify header presence before responding in these windows. A notification-opened or auto-resumed turn is still governed by R007 exactly like a user-input turn.

**Compaction-resume distinction**: resume instructions forbid *meta-preamble about the summary* (e.g. "continuing from the summary..."), not the *identification header*. The R007 header is a structural part of the response, not preamble, so no resume instruction waives it.

**Recurrence**: 2 omissions in the same 2026-08-18 session (both user-flagged via `@CLAUDE.md 재주입`); deferring the fix after the first ("harden the rule later") caused the second — an R016 "fix it later" anti-pattern in practice. A third omission occurred 2026-08-26, this time on an automatic post-compaction resume turn rather than a user-input turn: the resume directive to skip summary preamble was misapplied to the identification header itself.
