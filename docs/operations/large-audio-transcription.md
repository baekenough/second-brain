# 대용량 녹음 전사

클라우드 전사에 보내는 원본이 25 MiB를 넘거나 native diarize 모델에 보낼 오디오가 1,200초를 넘으면 collector의 ffmpeg가 임시 MP3(모노 16 kHz, 32 kbps)를 만들고 10분 단위로 나눕니다. 각 구간을 원격 전사 API에 순서대로 보냅니다. 로컬 추론은 하지 않습니다. 로컬 전사 엔드포인트와 작은 파일은 기존 경로를 사용합니다.

원본 오디오·사이드카·source ID·발생 시각은 바꾸지 않습니다. 모든 구간이 성공해야 문서 하나를 만들고 성공 원장을 기록합니다. 구간별 시작 시각은 ffmpeg가 기록한 실제 시각을 사용합니다. 독립 요청의 화자 번호를 동일인으로 연결하지 않으며, 본문에 구간 범위를 표시합니다. 임시 파일은 성공·실패·취소 모두에서 제거합니다.

재인코딩은 동시에 두 작업, 각 작업 한 스레드, 준비 시간 10분으로 제한합니다. 입력은 최대 24시간, 출력 합계는 최대 512 MiB이며 각 업로드는 기존 25 MiB 한도를 검사합니다. `WHISPER_MAX_FILE_BYTES` 운영 제한은 별도로 계속 적용됩니다. 24시간 초과·손상·변환 실패·원격 API 실패는 성공으로 기록하지 않습니다.

실패 상태는 오디오 루트의 `.transcription-retries/<경로 해시>.json`에 저장합니다. 파일 크기·수정 시각·고정 사유·다음 재시도 시각·비밀값을 제외한 설정 지문만 기록하며 파일명이나 전사 본문은 저장하지 않습니다. 6시간 뒤 다시 시도하고 원본이나 모델·엔드포인트·언어·청킹 설정이 바뀌면 즉시 재시도합니다. 이 디렉터리에 쓸 수 없는 경우 프로세스 메모리로 중복 시도를 막지만 재시작하면 다시 시도합니다. 운영자가 문제를 고친 뒤 즉시 재시도하려면 해당 상태 파일을 지우고 collector를 재시작하면 됩니다.

collector 이미지에만 ffmpeg/ffprobe를 설치합니다. 개발 환경에서 두 실행 파일이 없으면 재인코딩 테스트는 건너뜁니다. ffmpeg의 stderr와 원본 파일명은 로그·원격 multipart 파일명에 노출하지 않습니다.

2026-09-27 운영 API 검증에서 `gpt-4o-transcribe-diarize`는 1,800.028초 입력을 `invalid_value`로 거절하며 최대 길이 1,400초를 반환했습니다. 파일 크기 제한과 별개인 길이 제한이므로 25 MiB 미만 파일도 검사합니다. 작은 파일의 길이 확인이 실패하면 기존처럼 원격 API에 업로드해 유효성을 판단합니다. 이 정책 변경은 재시도 설정 지문 v2에 포함되어 이전 실패 대기 상태를 무효화합니다.
